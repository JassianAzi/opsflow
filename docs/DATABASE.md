# OpsFlow Database Design

This document defines the initial logical database model.

Phase 1 defines the four authentication and organization tables in
`apps/api/src/db/schema.ts`. The first versioned SQL migration is
`apps/api/drizzle/0000_soft_next_avengers.sql`. The later tables in this
document remain design targets and have not been created.

The exact ORM syntax may change, but the domain model should remain consistent unless the architecture is intentionally revised and documented.

## 1. Tables

### users

Fields:
- id
- email
- password_hash
- display_name
- created_at
- updated_at

Constraints:
- UUID primary key generated by PostgreSQL
- a unique index on `lower(email)`; the API stores trimmed, lowercased email
- timestamps use `timestamptz` with database defaults

### sessions

Fields:
- id
- user_id
- token_hash
- expires_at
- created_at
- last_seen_at

Constraints and behavior:
- UUID primary key and foreign key to `users.id` with cascade delete
- unique index on `token_hash`, indexes on `user_id` and `expires_at`
- token hash is SHA-256 of a random 32-byte opaque token; raw token is never stored
- logout deletes the session; expired sessions are rejected during lookup

### organizations

Fields:
- id
- name
- slug
- created_by
- created_at
- updated_at

Constraints:
- UUID primary key, unique slug, foreign key from `created_by` to `users.id`
- slug includes a random suffix to allow duplicate organization names

### organization_members

Fields:
- id
- organization_id
- user_id
- role
- created_at

Roles:
- owner
- member

Constraints:
- unique organization_id + user_id
- UUID primary key; foreign keys to organization and user with cascade delete
- database enum `organization_role` allows `owner` and `member`
- index on `user_id` supports membership lookups
- creation of the organization and initial owner membership is transactional

## 2. JSON Columns

PostgreSQL JSONB may be used for:
- trigger_config
- workflow step config
- retry_config
- trigger_payload
- step input_data
- step output_data
- audit metadata

JSON must not replace fields that need frequent indexing or relational integrity.

## 3. Tenant Isolation

Every tenant-owned resource must be traceable to an organization.

API queries must never retrieve organization-owned data without organization scoping.

Unsafe:

```sql
SELECT * FROM workflows WHERE id = $1;
```

Preferred:

```sql
SELECT * FROM workflows
WHERE id = $1
AND organization_id = $2;
```

## 4. Migrations

Rules:
- all schema changes require migrations
- never manually modify production-like schema without a migration
- migration files are committed
- destructive migrations must be explicitly documented

Run `npm run db:migrate` against the intended `DATABASE_URL`. Phase 1 generated
the migration with `npm run db:generate` and applied it to a dedicated
`opsflow_test` database. No seed data exists yet. API integration tests apply
committed migrations to a dedicated database named `opsflow_test` and clear
only their own fixture rows between tests.

## 5. Seed Data

Development seed data should include:
- one demo user
- one demo organization
- one sample workflow
- several execution histories with different statuses

Do not commit real credentials.
